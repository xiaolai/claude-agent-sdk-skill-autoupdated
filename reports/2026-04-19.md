**Likely cause**: Recurring stale-comma artifact in the Python template import line. The update agent generated an import like `from claude_agent_sdk import (,Symbol,...` with a leading comma after the opening parenthesis. This is a known recurring false positive — the comma appears when the template list is rebuilt with a leading separator.

**Suggested fix**: The typecheck script's import resolution check should strip leading/trailing commas from the import list before attempting to parse it, or the update agent's template generation should be fixed to not emit a leading comma.

### Verify — Exit Code 1 (3 attempts, 2 mend runs)

**Failures** (all 7 failures are the same root cause):
```
SKILL-typescript.md   — Still contains old version '0.2.114'
SKILL.md              — Still contains old TS version v0.2.114
plugin.json           — Description still has old v0.2.114
rules/claude-agent-sdk-ts.md — Still contains old v0.2.114
scripts/check-versions.sh   — Still contains old "0.2.114"
README.md             — Top section still contains old TypeScript v0.2.114
GLOBAL                — Stale TS version '0.2.114' found in 14 locations
```

**Root cause**: The verify script checks that the old version string no longer appears in the repository. When `oldVersion == newVersion == 0.2.114`, every legitimate reference to the current version is flagged as a "stale old version" — an unfixable condition. The mending agent correctly could not resolve this because the files _should_ contain `0.2.114`.

**Likely cause**: Structural bug in the verify script — it does not handle the no-version-change case (old == new). The check `grep -r "0.2.114"` will always find matches when the current version is `0.2.114`.

**Suggested fix**: In `verify.ts` (or equivalent), skip the stale-version grep check when `oldVersion === newVersion`. This scenario occurs regularly when the monitor detects registry dedup artifacts rather than a true version bump.
