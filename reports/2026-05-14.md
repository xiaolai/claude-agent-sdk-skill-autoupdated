## Errors

### Typecheck — exit code 1 (overridden to success)

This is the **recurring stale-comma false-positive** in the Python import resolution check. The typecheck script constructs a synthetic import line from the exported symbols list and encounters a stray leading comma `(,` in the generated `from claude_agent_sdk import (,...` statement, producing a `SyntaxError: invalid syntax`. This is a template check script artifact, not an actual code issue.

**Last output**:
```
=== Python import resolution check ===
  File "<string>", line 1
    from claude_agent_sdk import (,AgentDefinition,ClaudeAgentOptions,...
                                  ^
SyntaxError: invalid syntax
  FAIL: Some template imports don't resolve
  FAIL:   Cannot import: (

=========================================
  Passed: 13
  Failed: 2
=========================================

TEMPLATE CHECK FAILED — 2 issue(s)
```

**Likely cause**: The import list generation in the typecheck script produces a leading comma when the symbol list starts with a separator character. This is a script bug, not a documentation or SDK issue.

**Outcome override**: Pipeline `outcomes.typecheck` set to `"success"` — the mend agent corrected or bypassed this during the verify phase (verify passed 18/18 on attempt 2).

**Suggested fix**: Strip leading/trailing commas when assembling the import list in `scripts/typecheck.sh` (or equivalent).
